# TanStack Start starter for Wodby

A starter for the [Wodby TanStack Start service](https://github.com/wodby/service-tanstack-start) and
[TanStack Start stack](https://github.com/wodby/stack-tanstack-start).

It includes:

- [TanStack Start](https://tanstack.com/start) with React, file-based routing and Tailwind CSS
- a server function called during server rendering and from the browser
- the Nitro Node.js server output, started with `node .output/server/index.mjs`
- Wodby CI build, push, deployment and a post-deployment health check
- a lightweight health endpoint at `/healthz`

## Local development

```shell
npm install
npm run dev
```

Open http://localhost:3000. Edit `src/routes/index.tsx`; the page updates as
you save. Add a page by creating a file in `src/routes`; the route tree in
`src/routeTree.gen.ts` is regenerated by the development server.

Check types and run the production build locally:

```shell
npm run typecheck
npm run build
npm run start
```

## On Wodby

The pipeline in `.wodby/pipeline.yml` installs dependencies with `npm ci`, then
the service's image build runs `npm run build`. The container starts with
`npm run start` and listens on port 3000.

Runtime variables, including the database, Redis and mail variables of linked
services, are not available during the build. Read them in server functions,
server routes or middleware with `process.env`, at request time.

In a development workspace, Wodby starts Vite's development server with this
project's `vite.config.ts`. That file allows the environment's host names from
`WODBY_HOSTS`, which Vite needs to answer requests for them.
